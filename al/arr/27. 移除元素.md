### 一、先修正你的代码
题目要求：**返回新数组长度**，你最后 `return nums` 了，逻辑错误。
正确基础版（快慢指针/双指针同向）：
```js
/**
 * @param {number[]} nums
 * @param {number} val
 * @return {number}
 */
var removeElement = function (nums, val) {
  let index = 0; // 慢指针：记录有效元素位置
  for (let i = 0; i < nums.length; i++) { // 快指针：遍历所有元素
    if (nums[i] !== val) {
      nums[index] = nums[i];
      index++;
    }
  }
  return index;
};
```
测试：
```js
let arr = [3,2,2,3];
console.log(removeElement(arr, 3)); // 2
console.log(arr); // [2,2,2,3] 前两位有效，符合题意
```

## 二、其他解题思路（面试常问 3 种方案）
题目关键约束：
1. 原地修改、O(1) 额外空间
2. 元素**顺序可以改变**（这个条件是解题突破口）
3. 只关心前面有效部分，后面元素不用管

### 思路1：同向双指针（你原本的思路，标准解法）
#### 原理
- 慢指针 `index`：指向**下一个有效元素要存放的位置**
- 快指针 `i`：遍历整个数组
- 遇到不等于 `val` 的元素，就放到慢指针位置，慢指针后移
- 最终慢指针的值 = 新数组长度

#### 复杂度
- 时间：$O(n)$
- 空间：$O(1)$
- 特点：**保留原数组元素相对顺序**

---

### 思路2：左右对撞双指针（推荐，顺序可改变时最优）
利用题目「**顺序可以改变**」的条件，把待删除元素全部交换到数组尾部。

#### 原理
- 左指针 `left`：从头部开始，找等于 `val` 的元素（要删掉的）
- 右指针 `right`：从尾部开始，找不等于 `val` 的元素（有效元素）
- 左找到目标、右找到有效，两者交换；然后向中间收缩
- 最终 `left` 就是新长度

#### 代码实现
```js
var removeElement = function (nums, val) {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    // 左边遇到要删除的元素
    if (nums[left] === val) {
      // 把右侧有效元素换到左边
      nums[left] = nums[right];
      right--;
    } else {
      // 左边是有效元素，继续右移
      left++;
    }
  }
  return left;
};
```

#### 示例推演
`nums = [3,2,2,3], val = 3`
1. left=0, right=3：nums[0]=3 → 赋值 nums[0]=nums[3]=3，right=2
2. left=0, right=2：nums[0]=3 → 赋值 nums[0]=nums[2]=2，right=1
3. left=0, right=1：nums[0]=2≠3 → left=1
4. left=1, right=1：nums[1]=2≠3 → left=2
循环结束，返回 2 ✅

#### 优缺点
- 时间：$O(n)$，**交换次数更少**，数据量大时效率更高
- 空间：$O(1)$
- 缺点：**破坏原有元素顺序**（题目允许，所以完全可用）
- 面试加分：主动说出「利用顺序可打乱的条件，使用对撞双指针优化」

### 思路3：倒序遍历 + 数组删除（splice）
简单直观，适合新手理解，面试一般不推荐作为最优解，但可以作为补充思路。

#### 原理
从后往前遍历，遇到 `val` 直接 `splice` 删除。
> 为什么倒序？
> 正序删除会导致数组塌陷、索引错位，漏遍历元素；倒序无此问题。

#### 代码实现
```js
var removeElement = function (nums, val) {
  for (let i = nums.length - 1; i >= 0; i--) {
    if (nums[i] === val) {
      nums.splice(i, 1);
    }
  }
  return nums.length;
};
```

#### 优缺点
- 优点：代码极简、逻辑直观
- 缺点：`splice` 会移动数组元素，**时间复杂度退化为 $O(n^2)$**
- 适用：小规模数组，算法面试一般不首选

### 思路4：计数 + 覆盖（拓展思路，和同向双指针本质一致）
先统计有效元素个数，再统一覆盖数组前半部分，和方案1思想相同，写法不同：
```js
var removeElement = function (nums, val) {
  let count = 0;
  // 第一步：统计有效元素数量
  for (let n of nums) {
    if (n !== val) count++;
  }
  // 第二步：覆盖前 count 位
  let idx = 0;
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] !== val) {
      nums[idx++] = nums[i];
    }
  }
  return count;
};
```
纯拓展，性能和方案1一致，多一次遍历，不推荐。

## 三、四种方案对比 & 面试总结
| 方案 | 时间复杂度 | 空间 | 是否保序 | 面试推荐度 |
|------|------------|------|----------|------------|
| 同向双指针（快慢） | $O(n)$ | $O(1)$ | ✅ 保序 | ⭐⭐⭐⭐⭐（通用标准答案） |
| 对撞双指针 | $O(n)$ | $O(1)$ | ❌ 乱序 | ⭐⭐⭐⭐⭐（本题最优，利用题意） |
| 倒序+splice | $O(n^2)$ | $O(1)$ | ✅ 保序 | ⭐⭐（仅作思路补充） |
| 计数+覆盖 | $O(n)$ | $O(1)$ | ✅ 保序 | ⭐⭐（拓展了解） |

## 四、面试常问追问
1. **两种双指针怎么选？**
   - 题目要求**保留元素顺序**：用「同向快慢指针」
   - 题目允许**打乱顺序**：优先「左右对撞指针」，交换更少，效率更高

2. **为什么不建议用 splice？**
   splice 删除元素时，后面所有元素都会向前移位，数组操作开销大，大数据量下性能差。

3. **为什么倒序遍历删元素不会索引错乱？**
   正序删除后，后面元素前移，下一轮 `i++` 会跳过紧邻元素；倒序遍历从后往前删，不会影响前面未遍历的索引。
