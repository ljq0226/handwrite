# 前 K 个高频元素（LeetCode 347）手写题（Top K 经典题）
这是前端面试**哈希表 + Top K 算法方向的高频题**，字节、腾讯等大厂常考，核心考察**哈希统计、排序优化、堆/桶排序思想**，是所有 Top K 类问题的典型代表。

---

## 一、题目描述
给你一个整数数组 `nums` 和一个整数 `k` ，请你返回其中出现频率前 `k` 高的元素。你可以按**任意顺序**返回答案。

```js
// 示例1
输入: nums = [1,1,1,2,2,3], k = 2
输出: [1,2]

// 示例2
输入: nums = [1], k = 1
输出: [1]
```

### 核心考点
1. 哈希表的频率统计
2. Top K 问题的多种优化思路
3. 时间/空间复杂度的权衡
4. 堆、桶排序等数据结构的应用

---

## 二、三种主流解法（从入门到最优）
### 解法1：哈希表 + 排序（面试保底写法，最易实现）
#### 思路
1. 先用 `Map` 遍历数组，统计每个数字出现的频率
2. 将「数字-频率」键值对转为数组，按频率降序排序
3. 截取前 `k` 个元素，提取数字返回

#### 代码实现
```js
/**
 * @param {number[]} nums
 * @param {number} k
 * @return {number[]}
 */
var topKFrequent = function(nums, k) {
  // 1. 哈希表统计频率
  const freqMap = new Map();
  for (const num of nums) {
    freqMap.set(num, (freqMap.get(num) || 0) + 1);
  }

  // 2. 按频率降序排序
  const sorted = Array.from(freqMap.entries()).sort((a, b) => b[1] - a[1]);

  // 3. 取前k个的数字部分
  return sorted.slice(0, k).map(item => item[0]);
};
```

#### 复杂度分析
- **时间复杂度**：O(n log n)
  统计频率O(n)，排序最坏情况（所有元素都不同）是O(n log n)
- **空间复杂度**：O(n)
  哈希表最坏存储n个键值对

#### 优缺点
- ✅ 写法简单直观，不容易写错，面试保底首选
- ❌ 排序有额外开销，数据量大时效率不高

### 解法2：桶排序（时间最优，O(n)，面试加分项）
#### 思路
利用「频率的最大值不会超过数组长度」的特点，用**数组下标代表频率**，对应位置存储该频率的所有数字（桶）：
1. 哈希表统计频率
2. 创建桶数组，下标为频率，值为对应频率的数字列表
3. 从后往前（频率从高到低）遍历桶，收集元素直到凑够 `k` 个

#### 代码实现
```js
var topKFrequent = function(nums, k) {
  const freqMap = new Map();
  for (const num of nums) {
    freqMap.set(num, (freqMap.get(num) || 0) + 1);
  }

  // 创建桶：下标为频率，值为数字数组
  // 最大频率 = 数组长度，所以桶长度设为 nums.length + 1
  const buckets = new Array(nums.length + 1);
  for (const [num, freq] of freqMap.entries()) {
    if (!buckets[freq]) {
      buckets[freq] = [];
    }
    buckets[freq].push(num);
  }

  // 从高频率到低频率收集结果
  const res = [];
  for (let i = buckets.length - 1; i >= 0 && res.length < k; i--) {
    if (buckets[i]) {
      res.push(...buckets[i]);
      // 超过k个时截断
      if (res.length > k) {
        res.length = k;
      }
    }
  }

  return res;
};
```

#### 复杂度分析
- **时间复杂度**：O(n)
  统计频率、入桶、遍历收集均为线性时间
- **空间复杂度**：O(n)
  哈希表 + 桶数组，总空间不超过n

#### 优缺点
- ✅ 时间复杂度最优，纯线性时间
- ❌ 频率范围极大时会浪费空间（本题频率最大为数组长度，完全适用）

### 解法3：小顶堆（经典 Top K 通用解法，大数据场景最优）
#### 思路
维护一个**大小为 k 的最小堆**，堆顶是当前前k个元素中频率最小的：
1. 遍历所有「数字-频率」对
2. 堆的大小小于k时，直接入堆
3. 堆的大小等于k时，若当前频率大于堆顶频率，则弹出堆顶，将当前元素入堆
4. 遍历结束后，堆中元素就是前k高频的元素

> 为什么用小顶堆不用大顶堆？
> 小顶堆可以用O(k)空间维护前k大元素，每次只需要和堆顶比较；大顶堆需要全量入堆，空间O(n)，没有优势。

#### 代码实现（手写最小堆）
```js
var topKFrequent = function(nums, k) {
  // 1. 统计频率
  const freqMap = new Map();
  for (const num of nums) {
    freqMap.set(num, (freqMap.get(num) || 0) + 1);
  }

  // 2. 实现最小堆（按频率排序）
  class MinHeap {
    constructor() {
      this.heap = [];
    }
    // 入堆
    push(val) {
      this.heap.push(val);
      this._up(this.heap.length - 1);
    }
    // 弹出堆顶
    pop() {
      if (this.heap.length === 0) return null;
      const top = this.heap[0];
      const last = this.heap.pop();
      if (this.heap.length > 0) {
        this.heap[0] = last;
        this._down(0);
      }
      return top;
    }
    // 获取堆顶
    peek() {
      return this.heap[0];
    }
    size() {
      return this.heap.length;
    }
    // 向上调整
    _up(index) {
      while (index > 0) {
        const parent = Math.floor((index - 1) / 2);
        if (this.heap[index][1] < this.heap[parent][1]) {
          [this.heap[index], this.heap[parent]] = [this.heap[parent], this.heap[index]];
          index = parent;
        } else break;
      }
    }
    // 向下调整
    _down(index) {
      const len = this.heap.length;
      while (true) {
        const left = index * 2 + 1;
        const right = index * 2 + 2;
        let minIdx = index;
        if (left < len && this.heap[left][1] < this.heap[minIdx][1]) minIdx = left;
        if (right < len && this.heap[right][1] < this.heap[minIdx][1]) minIdx = right;
        if (minIdx === index) break;
        [this.heap[index], this.heap[minIdx]] = [this.heap[minIdx], this.heap[index]];
        index = minIdx;
      }
    }
  }

  // 3. 维护大小为k的小顶堆
  const heap = new MinHeap();
  for (const entry of freqMap.entries()) {
    if (heap.size() < k) {
      heap.push(entry);
    } else {
      if (entry[1] > heap.peek()[1]) {
        heap.pop();
        heap.push(entry);
      }
    }
  }

  // 4. 收集堆中元素
  const res = [];
  while (heap.size() > 0) {
    res.push(heap.pop()[0]);
  }
  return res; // 题目允许任意顺序
};
```

#### 复杂度分析
- **时间复杂度**：O(n log k)
  每个元素最多入堆一次，堆操作是O(log k)，总共有m个不同元素，最坏m=n
- **空间复杂度**：O(k)（不计哈希表）
  堆的大小始终不超过k，适合内存有限的大数据场景

#### 优缺点
- ✅ 空间效率高，是大数据量 Top K 问题的标准解法
- ✅ 通用性强，所有 Top K 场景都适用
- ❌ 需要手写堆，代码量稍大

## 三、三种方案对比
| 方案 | 时间复杂度 | 空间复杂度 | 面试推荐度 | 核心适用场景 |
|------|------------|------------|------------|--------------|
| 哈希表+排序 | O(n log n) | O(n) | ⭐⭐⭐⭐ | 数据量小，快速实现，保底写法 |
| 桶排序 | O(n) | O(n) | ⭐⭐⭐⭐⭐ | 频率范围有限，追求线性时间，加分首选 |
| 小顶堆 | O(n log k) | O(k) | ⭐⭐⭐⭐⭐ | 大数据量Top K，内存有限，通用解法 |

## 四、面试必问延伸问题
### 1. 找前 K 大为什么用小顶堆，不用大顶堆？
**答案：**
小顶堆的堆顶是当前K个元素里最小的，新元素只要比堆顶大就可以替换入堆，遍历完所有数据后，堆里就是前K大的元素。
如果用大顶堆，需要把所有元素都入堆才能找到前K大，空间复杂度是O(n)，没有优势。
简单记：**找前K大用小顶堆，找前K小用大顶堆**。

### 2. 如果数据量特别大，内存装不下整个数组怎么办？
**答案：**
可以用分治+多路归并的思路：
1. 把大文件切分成多份，每份分别统计频率、求前K高频
2. 把所有分片的结果汇总，再用小顶堆求全局前K高频
也可以用MapReduce分布式思想，分片处理后合并结果。

### 3. 桶排序有什么局限性？
**答案：**
桶排序依赖「数据范围有限」的前提。如果频率的取值范围极大（比如频率从1到1e9），桶数组会占用大量空间甚至无法创建。
本题中频率最大等于数组长度，范围可控，因此桶排序是最优解。

### 4. O(n) 的算法一定比 O(n log n) 快吗？
**答案：**
不一定。数据量很小时，排序的常数项更低，反而可能更快；只有当数据量足够大时，线性时间的优势才会体现出来。算法选择要结合实际数据规模。

## 五、面试回答话术
> 这道题是经典的Top K问题，我有三种主流解法。
> 
> 最基础的是哈希表统计频率后排序取前k个，写法简单，时间复杂度O(n log n)。
> 针对本题还可以用桶排序优化，因为频率最大不会超过数组长度，我们用频率作为桶的下标，从后往前收集前k个元素，时间复杂度可以降到O(n)。
> 如果是大数据量、内存有限的场景，我会用大小为k的小顶堆来做，遍历所有频率，比堆顶大就替换入堆，空间只需要O(k)，时间复杂度是O(n log k)，这也是Top K问题的通用解法。
> 
> 其中桶排序在本题场景下时间最优，小顶堆适用性更广。
