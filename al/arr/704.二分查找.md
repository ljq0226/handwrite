# 二分查找（LeetCode 704）手写题（算法基础必考题）
这是**所有二分变种的母题**，是大厂前端面试算法部分的高频基础题，核心考察**边界条件处理能力**、**有序数组的优化思想**和**代码严谨性**，几乎所有算法面试都会从这道题延伸出变种问题。

---

## 一、基础题（必背，100% 掌握）
### 题目描述
给定一个 `n` 个元素的**升序整型数组** `nums` 和一个目标值 `target`，写一个函数搜索 `nums` 中的 `target`。如果目标值存在返回下标，否则返回 `-1`。

```js
// 示例1
输入: nums = [-1,0,3,5,9,12], target = 9
输出: 4
解释: 9 出现在 nums 中并且下标为 4

// 示例2
输入: nums = [-1,0,3,5,9,12], target = 2
输出: -1
解释: 2 不存在 nums 中，因此返回 -1
```

### 核心思想
利用数组**有序（单调）**的特性，每次通过中间值排除一半的搜索范围，将线性查找的 O(n) 时间复杂度优化到 O(log n)。

---

### 标准写法1：左闭右闭区间 `[left, right]`（面试首选，最不易错）
这是最直观、最推荐的写法，区间定义为「左右边界都包含有效元素」，全程保持定义一致即可。

```js
/**
 * @param {number[]} nums 升序数组
 * @param {number} target 目标值
 * @return {number} 目标值下标，不存在返回-1
 */
var search = function(nums, target) {
  // 边界处理
  if (nums.length === 0) return -1;

  let left = 0;
  let right = nums.length - 1; // 右边界是最后一个元素下标，闭区间

  while (left <= right) { // 闭区间：left === right 时，区间还有1个元素，有意义
    // 计算中间下标，避免 left + right 溢出（通用规范写法）
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      return mid; // 找到目标，直接返回
    } else if (nums[mid] > target) {
      // mid 比目标大，目标在左半区
      // mid 肯定不是答案，右边界收缩到 mid-1
      right = mid - 1;
    } else {
      // mid 比目标小，目标在右半区
      // mid 肯定不是答案，左边界收缩到 mid+1
      left = mid + 1;
    }
  }

  // 循环结束没找到，返回-1
  return -1;
};
```

#### 核心原则（闭区间）
- 循环条件：`left <= right`
- 大于目标：`right = mid - 1`
- 小于目标：`left = mid + 1`

---

### 标准写法2：左闭右开区间 `[left, right)`
另一种常见写法，区间定义为「左边界包含，右边界不包含」，对应边界更新逻辑会变化。

```js
var search = function(nums, target) {
  let left = 0;
  let right = nums.length; // 右边界是数组长度，开区间，不包含该位置

  while (left < right) { // 开区间：left === right 时空区间，无意义
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      return mid;
    } else if (nums[mid] > target) {
      // 目标在左半区，开区间右边界直接等于mid（mid不包含）
      right = mid;
    } else {
      // 目标在右半区，闭区间左边界要+1
      left = mid + 1;
    }
  }

  return -1;
};
```

#### 核心原则（开区间）
- 循环条件：`left < right`
- 大于目标：`right = mid`
- 小于目标：`left = mid + 1`

---

### 常见致命坑点（90% 候选人会踩）
1. **mid 计算溢出**
   ```js
   // ❌ 错误写法：left + right 可能超出整数范围（语言层面溢出）
   const mid = Math.floor((left + right) / 2);
   // ✅ 正确写法：差值法，永远不会溢出
   const mid = left + Math.floor((right - left) / 2);
   ```

2. **区间定义与边界更新不匹配**
   这是最核心的扣分点：比如用左闭右开区间，却写 `right = mid - 1`，会导致漏查元素或死循环。
   > 面试口诀：**定义好区间后，全程保持边界逻辑和区间定义一致**。

3. **循环条件写错**
   闭区间用 `left < right` 会漏掉 `left===right` 那个元素；开区间用 `left <= right` 会越界访问。

4. **忽略空数组、单元素数组等边界场景**

## 二、字节高频变体题（按考察频率排序）
### 变体1：查找第一个等于 target 的位置（左边界二分，LeetCode 34）
#### 题目描述
数组存在重复元素，返回**第一个**等于 target 的下标，不存在返回 -1。
```js
输入: nums = [1,2,2,2,3], target = 2
输出: 1
```

#### 实现代码（左闭右闭版）
```js
var searchLeftBound = function(nums, target) {
  let left = 0;
  let right = nums.length - 1;
  let res = -1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    if (nums[mid] === target) {
      res = mid; // 记录当前位置，继续往左找更早的
      right = mid - 1; // 收缩右边界，继续向左找
    } else if (nums[mid] > target) {
      right = mid - 1;
    } else {
      left = mid + 1;
    }
  }

  return res;
};
```

### 变体2：查找最后一个等于 target 的位置（右边界二分，LeetCode 34）

输入: nums = [1,2,2,2,3], target = 2

var searchRightBound = function(nums, target) {

### 变体3：模糊查找（第一个大于等于 target 的位置）
#### 题目描述
查找第一个大于等于 target 的元素下标（即 lower_bound），常用于插入位置问题（LeetCode 35）。
```js
输入: nums = [1,3,5,6], target = 2
输出: 1
解释: 2 应该插入到下标1的位置
```

#### 实现代码
```js
var searchInsert = function(nums, target) {
  let left = 0;
  let right = nums.length - 1;
  let res = nums.length; // 默认插入到末尾

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    if (nums[mid] >= target) {
      res = mid;
      right = mid - 1;
    } else {
      left = mid + 1;
    }
  }

  return res;
};
```

## 三、核心考察点（面试必说）
1. **前提条件**：数组必须具有**单调性（有序）**，这是二分查找的必要条件
2. **时间复杂度**：O(log n)，每次排除一半数据，n 个元素最多需要 log₂n 次查找
3. **空间复杂度**：O(1)，仅使用常数个变量，原地查找
4. **边界一致性**：区间定义（闭/开）必须和循环条件、边界更新逻辑全程匹配
5. **变种扩展**：可以扩展出左边界、右边界、模糊查找等多种场景

## 四、面试必问延伸问题（标准答案）
### 1. 二分查找的时间复杂度为什么是 O(log n)？
**答案：**
每次查找都会排除一半的元素，搜索空间从 n 变成 n/2、n/4...直到剩下1个元素。
设查找次数为 k，则 n / 2ᵏ = 1 → k = log₂n，因此时间复杂度是 O(log n)。

### 2. 左闭右闭和左闭右开怎么选？有什么区别？
**答案：**
- 左闭右闭逻辑更直观，边界清晰，不容易写错，面试优先写这个
- 左闭右开在处理数组切片、区间划分时更自然，很多语言的原生API（如 splice）是开区间设计
- 本质没有优劣，**核心是全程保持区间定义一致**，不要混用。

### 3. 数组有重复元素还能用二分查找吗？
**答案：**
可以。基础二分只能找到任意一个匹配项；如果要找第一个/最后一个匹配项，就用左右边界二分法，本质是在找到目标值后不立即返回，继续收缩边界查找。

### 4. 二分查找只能用在数组上吗？
**答案：**
不是。只要是**有序、可随机访问**的结构都可以用二分查找，比如有序数组、二叉搜索树、答案区间（二分答案类问题）。
链表不能用二分查找，因为链表无法 O(1) 访问中间元素。

### 5. 为什么 mid 要向下取整？向上取整行不行？
**答案：**
基础二分查找向下、向上取整都可以，只要逻辑一致。
但在左右边界查找、二分答案等场景中，取整方向必须和边界收缩方向匹配，否则会出现死循环。
比如找右边界时，如果用向上取整，需要对应调整边界逻辑，避免死循环。

## 五、面试回答思路（直接背）
> 这道题是经典的二分查找基础题，我会用左闭右闭的区间来实现。
> 
> 首先定义左右指针分别指向数组首尾，循环条件是 left 小于等于 right，因为闭区间中左右相等时还有一个有效元素。
> 每次计算中间下标 mid，为了避免溢出，我用 left + (right-left)/2 的方式计算。
> 如果中间值等于目标值就直接返回；如果中间值更大，说明目标在左半区，把右边界移到 mid-1；如果更小，就把左边界移到 mid+1。
> 循环结束没找到就返回 -1。
> 
> 这个写法的时间复杂度是 O(logn)，空间复杂度 O(1)。在此基础上还可以扩展出查找左边界、右边界、插入位置等变种，核心都是保持区间定义和边界更新一致。
